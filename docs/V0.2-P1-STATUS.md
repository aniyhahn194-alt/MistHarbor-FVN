### 3.4 过程中发现并处理的问题

- 手机视口模拟下的存读档第一次运行 **FAIL**：原因是测试脚本仍去点触屏下已隐藏的“快存”按钮，不是游戏缺陷；脚本改为点触屏下的“保存”按钮后重跑通过。

## 6. 如何在手机上验收（需所有者批准，目前均未执行）

目前**没有**预览链接。仓库里的 `.github/workflows/web-build-pages.yml` 仅手动触发，输入 `publish`：

| 方案 | 做法 | 影响 / 风险 |
| --- | --- | --- |
| A. 仅构建，不发布 | 在 Actions 里对本分支手动运行，`publish=no` | 只产出仅协作者可下载的 Artifact（zip），手机无法直接试玩；可用来在云端复核构建 |
| B. 发布到 Pages（**会覆盖当前公开的 V0.1**） | 所有者批准后，对本分支或合并后的 `main` 运行，`publish=yes` | 公开站点只有一个，V0.2-P1 会替换 V0.1；V0.1 的 zip 仍保存在 Project store 以便回滚。本分支能否部署到 Pages 取决于仓库 Pages / environment 的分支规则，**未验证** |
| C. 独立预览（itch.io 受限 / 密码页等） | 需要所有者的账号并上传 `MistHarbor-0.2.0-p1-web.zip` | 不影响公开 V0.1；需要账号授权，**未验证** |

推荐：所有者确认“可以替换公开的 V0.1”后走 B（合并 PR 之后用 `main` 发布最干净）；若希望 V0.1 在验收期间保持公开，则走 C。没有批准前，以上都**不会**执行。
