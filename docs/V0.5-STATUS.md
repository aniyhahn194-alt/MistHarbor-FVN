# V0.5 状态：已实现 / 未实现 / 测试结果 / 未验证

版本：`0.5.0`（`game/options.rpy`）。分支 `cursor/v0-5-art-polish-f5eb`，Draft PR，**未合并、未部署**；`main` 与当前公开的试玩版本不受影响。
美术 / UI 规范与本轮做法见 [V0.5-ART-UI-BRIEF.md](V0.5-ART-UI-BRIEF.md)；给画师的完整需求见 [ART_BRIEF.md](ART_BRIEF.md)；上一轮记录见 [V0.2-P1-STATUS.md](V0.2-P1-STATUS.md)。

> **术语约定**：**“桌面 Chromium 模拟”** 指在桌面 Google Chrome（Playwright，软件渲染 SwiftShader）里设置手机视口（844×390 / 932×430 / 667×375）、触控、DPR 2、iPhone UA；它**不是**真实手机，更不是 iOS Safari。本文所有“手机”结果都属于这一类，**没有任何真机测试**。

> **美术声明**：背景、立绘后期、加载画面、界面图全部由 Python + Pillow 代码绘制 / 处理，**是程序化占位美术，不是专业手绘**；没有使用 AI 图像生成工具，没有抓取网络图片。立绘仍是几何造型，只是“更融入背景”，不是“重画”。

## 2. 未实现 / 已知限制

- **专业立绘 / 背景 / CG**：没有。现有仍是程序化占位美术；立绘造型、解剖、表情、毛发、手部、服饰细节都没有改善，只改善了与背景的融合度。需求更新见 [V0.5-ART-UI-BRIEF.md](V0.5-ART-UI-BRIEF.md) 第 4 节
- **对话框遮挡腿脚**：立绘缩放 0.56、底边对齐，对话框会盖住腰部以下，所以脚下投影只有在选项页（对话框之外的区域）才可能看到；没有为此改变站位 / 缩放（改小会损害手机上脸部可读性）
- **Web 加载状态文字**仍是官方英文（`Unpacking...` / `Loading script...`），只改了外观，没有改文字（会需要深度改写官方 `index.html`）
- **首次进入主菜单变慢**：增加了 2.2 秒的 splash（可点击跳过）和约 +4.5 MiB 资源（背景含颗粒后每张约 0.75 MB，presplash 约 0.45 MB）。同一台机器同一本地服务器、无限速下，首次到主菜单的耗时由 7–9 秒增至 11–14 秒（见 3.3；含 splash 的 2.2 秒）。公网下的耗时**未验证**
- 音乐 / 音效 / 语音；结局回顾；新剧情；新系统；手机竖屏专门布局
- 触屏“快存 / 快读”仍隐藏（沿用 V0.2）
- GitHub Pages 部署 / 公开预览（需所有者批准，见第 5 节）

### 3.4 过程中发现并处理的问题（如实记录）

1. **官方 CLI `web_build` 忽略项目 `web-presplash.png`**：第一次构建后检查产物，`index.html` 仍引用 Ren'Py 默认图，自制图只被当作普通文件塞进了 `game.zip`。已在 `build_web.sh` 中补做并加了校验，见 3.2。
2. **testcase 与 splashscreen 冲突**：见 3.1 的说明。
3. **测试脚本的“画面停住”判读**被呼吸 / 灯光动画干扰，导致第一次浏览器流程“推进剧情超过最大步数”失败；改为只比较对话框中段、不含立绘的区域。同时“等主菜单稳定”的阈值太严（主菜单本来就有持续的光束 / 雾动画，相邻 1 秒约 3% 像素不同），第二次分支运行因此超时，已放宽到约 9%。这两处都是**测试脚本**的问题，不是游戏缺陷；前后对比用的是同一份修正后的脚本。
4. 立绘第一版后期偏褐、边缘光过硬；月亮与灯塔位置曾与角色头部 / 标题重叠，已调整。

## 5. iPhone 预览与需要所有者批准的步骤（本轮**未执行**）

**现状**：公开的 GitHub Pages 是已部署的旧版本；本 PR 没有部署，也没有运行 `web-build-pages.yml`。手机不能直接“打开 zip”，必须有一个 https 网址。

**需要所有者批准 / 操作的步骤**（顺序）：

1. 评审本 Draft PR 的截图与文档，决定是否接受外观。
2. （可选，不公开）在 GitHub Actions 里手动运行 `web-build-pages.yml`，分支选本 PR 分支，`publish` 保持 `no`：只会得到私有 Artifact（zip + SHA256），用来核对 CI 能否构建成功。此 workflow **尚未在 Actions 上为本分支运行过**（本地只验证了它调用的 `tools/build_web.sh`）。
3. 想在 iPhone 上看到 V0.5：需要把它发布到一个 https 网址。Pages 只有一个站点，**发布会替换当前公开的版本**；`github-pages` 环境默认只允许默认分支部署。可选做法：先合并本 PR 再用 `publish=yes` 运行；或所有者在 Settings → Environments → github-pages 放宽分支限制后从本分支运行（会让公开站点立刻变成 V0.5）；或把 Project store 里的 zip 上传到所有者自己的临时静态托管（itch.io 受限页、Cloudflare Pages 等）单独预览。以上均需所有者操作和确认，我没有做。
4. 发布后在 iPhone（Safari）**横屏**打开，按下面清单验收，并把结果反馈。
